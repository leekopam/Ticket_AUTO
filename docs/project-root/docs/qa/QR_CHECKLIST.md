# QR_CHECKLIST — Quality Review Checklist

QR은 Quality Review를 의미한다. 작업 완료 전 이 체크리스트로 요구사항 누락, 회귀, 검증 누락, 사용자 피드백 반영 여부를 확인한다.

## A. 요구사항 및 범위

- [ ] 사용자의 이번 작업 요구사항을 모두 반영했다.
- [ ] 금지 조건을 위반하지 않았다.
- [ ] 수정 범위를 벗어나지 않았다.
- [ ] 기능 변경과 리팩터링을 불필요하게 섞지 않았다.
- [ ] 기존 정상 기능을 근거 없이 수정하지 않았다.

## B. 코드 품질

- [ ] 결합도는 낮고 응집도는 높게 유지했다.
- [ ] 기존 프로젝트 컨벤션을 따랐다.
- [ ] 에러 처리를 조용히 삼키지 않았다.
- [ ] 외부 입력/저장 데이터/네트워크 응답은 경계에서 검증했다.
- [ ] 새 의존성이 있다면 이유와 대안을 남겼다.

## C. UI/UX 품질

- [ ] Loading 상태가 있다.
- [ ] Success 상태가 있다.
- [ ] Empty 상태가 있다.
- [ ] Error 상태와 복구 행동이 있다.
- [ ] Disabled 상태의 이유가 필요한 곳에서 설명된다.
- [ ] 접근성, 포커스, 터치 타겟, 긴 텍스트, 반응형을 검토했다.
- [ ] 사용자 문구가 자연스러운 한국어다.

## D. 테스트 및 검증

- [ ] 자동 테스트를 실행했다.
- [ ] 빌드/린트/타입체크 중 가능한 항목을 실행했다.
- [ ] 수동 QA 절차를 남겼다.
- [ ] 실행하지 못한 검증은 이유와 실행 명령을 남겼다.
- [ ] 회귀 위험이 큰 기존 흐름을 확인했다.

## E. 작업 이력 및 피드백

- [ ] 의미 있는 시도/실패/성공을 `docs/ai-worklog/attempt-log.md`에 기록했다.
- [ ] 사용자 피드백을 `docs/ai-worklog/user-feedback.md`에 반영했다.
- [ ] 중복되거나 긴 내용은 `docs/ai-worklog/context-summary.md`로 압축했다.
- [ ] 같은 실패를 반복하지 않았는지 확인했다.

## F. 완료 보고

- [ ] 변경 파일 목록을 보고했다.
- [ ] 검증 결과를 보고했다.
- [ ] 남은 리스크를 보고했다.
- [ ] 롤백 포인트를 보고했다.
