스캔 중 연속 AF를 끄고, 근거리 수동 초점으로 잠그기

OpenCV는 CAP_PROP_FOCUS, CAP_PROP_AUTOFOCUS, CAP_PROP_SETTINGS, CAP_PROP_AUTO_EXPOSURE를 노출하고, DirectShow 쪽 focus 값/범위는 기기별로 다르다. 그래서 manual_focus_value를 config로 저장해두고, 스캔 때는 AF off + fixed focus로 두는 방식이 가장 현실적이야. OpenCV cap.set()이 잘 안 먹는 카메라면, CAP_PROP_SETTINGS로 DSHOW 설정창을 띄우거나, Windows용 오픈소스인 FocusUF / duvc-ctl로 focus·exposure를 외부에서 잠그는 방법도 바로 쓸 수 있어. 

def _prepare_scan_focus(self, cap: cv2.VideoCapture) -> None:
    try:
        if hasattr(cv2, "CAP_PROP_AUTOFOCUS"):
            cap.set(cv2.CAP_PROP_AUTOFOCUS, 0)
        if hasattr(cv2, "CAP_PROP_FOCUS") and self._manual_focus_value is not None:
            cap.set(cv2.CAP_PROP_FOCUS, float(self._manual_focus_value))
    except Exception:
        pass
핵심은 _prepare_scan_focus()를 카메라 open 시점에만 호출하고, set_auth_ready() / set_scanning_enabled()에서는 더 이상 autofocus를 다시 켜지 않는 거야.

pyzbar는 그대로 두고 QR만 보게 제한하기
지금 _decode_qr()는 decode(frame) 기본 동작을 쓰는데, pyzbar 기본은 모든 심볼 타입을 찾는다. symbols=[ZBarSymbol.QRCODE]로 제한하면 방식은 그대로 유지하면서 검사 범위를 줄일 수 있어. 참고로 pyzbar는 color numpy.ndarray를 받으면 내부에서 첫 번째 채널만 꺼내 8bpp로 처리하므로, 매 프레임 cvtColor()를 넣는 건 “무조건 더 빠르다”라고 보기 어렵다. 그래서 먼저 QR-only만 적용하고, grayscale은 실패 프레임에만 2차 pass로 넣는 편이 더 안전해. 

from pyzbar.pyzbar import decode, ZBarSymbol

results = decode(frame, symbols=[ZBarSymbol.QRCODE])
if not results:
    gray = cv2.cvtColor(frame, cv2.COLOR_BGR2GRAY)
    results = decode(gray, symbols=[ZBarSymbol.QRCODE])
중앙 ROI 먼저 보고, 실패할 때만 전체 프레임 fallback

h, w = frame.shape[:2]
x1, y1 = int(w * 0.2), int(h * 0.2)

노출도 같이 고정하는 쪽이 유리할 수 있음

정리해서 바로 답하면: 조건부로 가능해.
프로그램 안에 “수동 초점 슬라이더/버튼”을 넣는 건 가능하지만, 실제로 렌즈 초점을 움직일 수 있는지는 웹캠 하드웨어와 드라이버가 focus control을 밖으로 노출하느냐에 달려 있어. Windows 쪽에서는 IAMCameraControl/CameraControl_Focus로 초점 속성을 다룰 수 있고, 자동/수동 플래그도 따로 있지만, Microsoft 문서도 초점 범위와 기본값은 기기별이고, 어떤 기기는 그 속성의 일부만 구현할 수 있다고 명시해. OpenCV도 CAP_PROP_FOCUS, CAP_PROP_AUTOFOCUS, CAP_PROP_SETTINGS를 제공하지만, 공식 문서에서 실제 동작은 하드웨어·드라이버·백엔드에 따라 달라진다고 못 박고 있어. 

그래서 네 질문에 대한 가장 정확한 답은 이거야.
앱이 “수동 초점 기능”을 새로 만들 수는 있지만, 그건 어디까지나 웹캠이 원래 가지고 있는 focus control을 호출하는 UI/로직을 만드는 거야.
웹캠이 고정초점(fixed focus) 이거나, 렌즈가 움직이더라도 드라이버가 그 제어를 노출하지 않으면, 앱이 없는 하드웨어 기능을 새로 만들어서 진짜 초점을 바꾸는 건 못 해. Windows의 최신 카메라 컨트롤 문서도 수동 초점/연속 AF/UI 슬라이더 같은 기능은 모두 장치가 지원하는 범위(Supported, Min, Max, Step) 안에서만 제공된다고 설명해. 

네 상황에 맞춰 실전적으로 보면, 확인 순서는 이게 제일 좋아.

OpenCV에서 먼저 지원 여부를 프로브

import cv2

cap = cv2.VideoCapture(0, cv2.CAP_DSHOW)

print("AUTOFOCUS before:", cap.get(cv2.CAP_PROP_AUTOFOCUS))
print("FOCUS before:", cap.get(cv2.CAP_PROP_FOCUS))

ok_af = cap.set(cv2.CAP_PROP_AUTOFOCUS, 0)
ok_focus = cap.set(cv2.CAP_PROP_FOCUS, 10)

print("set AF off:", ok_af)
print("set focus:", ok_focus)
print("FOCUS after:", cap.get(cv2.CAP_PROP_FOCUS))

# DSHOW 드라이버 설정창 띄우기
cap.set(cv2.CAP_PROP_SETTINGS, 0)

cap.release()
이 테스트에서 봐야 하는 건 세 가지야.
CAP_PROP_SETTINGS로 뜨는 드라이버 설정창에 focus/manual 항목이 있으면 generic Windows 경로로 제어 가능한 가능성이 높고, set(CAP_PROP_FOCUS, ...)가 성공하면서 실제 화면도 변하면 앱에서 슬라이더를 붙일 수 있어. 반대로 set()이 실패하거나 값이 안 바뀌고, 설정창에도 focus 관련 항목이 없으면 현재 장치/드라이버 조합에서는 일반적인 방법으로 수동 초점 구현이 어렵다고 보면 된다. OpenCV 쪽은 공식적으로도 property set/get 결과가 하드웨어·드라이버·백엔드에 따라 달라질 수 있고, CAP_PROP_SETTINGS는 DSHOW에서만 지원된다고 안내한다. 

OpenCV가 애매하면 Windows 레벨에서 직접 확인
Windows에서는 IAMCameraControl의 GetRange/Get/Set으로 카메라 속성을 직접 조회·설정할 수 있어. GetRange(CameraControl_Focus, ...)가 성공하면 초점 제어 범위가 있다는 뜻이고, 자동/수동 플래그도 별도로 존재한다. 반대로 그 경로에서 focus property를 못 얻으면, 적어도 표준 Windows 캡처 경로로는 수동 초점 지원이 없다고 보는 게 맞아. 

지원되면 네 프로젝트에 넣을 구현 방식
가장 좋은 형태는 **“초점 보정 모드”**를 하나 두는 거야.
처음 한 번만 사용자가 슬라이더로 휴대폰 QR이 제일 선명한 지점을 맞추고, 그 값을 설정 파일에 저장한 다음, 스캔 시작 시에는:

AUTOFOCUS = 0

FOCUS = 저장된 값

가능하면 AUTO_EXPOSURE도 끄고 고정

이렇게 적용해. 자동초점이 켜진 상태에서는 수동 초점 요청이 무시되거나 의미가 애매해질 수 있고, Linux V4L2 문서도 AF가 켜져 있으면 수동 focus 조정은 무시해야 한다고 설명한다. Windows도 auto/manual를 별도 플래그로 관리한다. 즉 스캔 중에는 AF를 끄고 고정값으로 잠그는 설계가 맞다. 

지원이 안 되면 결론은 사실상 이거야
그 경우엔 프로그램으로 “진짜 수동 초점”을 넣는 건 어렵고, 대신 초점이 잘 맞는 물리 거리로 휴대폰 위치를 고정하는 쪽이 가장 효과적이야. 예를 들면 휴대폰을 렌즈에서 15~25cm 같은 일정 거리로 멈추게 하는 가이드, QR 표시 크기 확대, 화면 밝기 고정, 주변 조명 확보, 중앙 ROI 우선 디코드 같은 쪽이 현실적인 개선책이 된다. 이건 초점 자체를 바꾸는 건 아니지만, 네 현재 방식의 안정성을 유지하면서 체감 속도를 줄이는 데는 꽤 유효해. OpenCV/Windows 문서상으로도 앱이 쓸 수 있는 카메라 제어는 결국 장치가 노출한 capability 범위 안에서만 가능하다.

수정된 전체 scanner_view.py

지금 scanner_view.py는 set_auth_ready()와 set_scanning_enabled()에서 다시 _enable_autofocus(cap)를 호출하고, 카메라를 열 때도 _open_camera_with_fallback()에서 autofocus를 켠 뒤, QR 디코드는 decode(frame) 그대로 쓰고 있다. 그래서 Auto/Manual 겸용으로 바꾸려면 “상태 전환 때마다 AF를 다시 켜는 구조”부터 끊는 게 맞다. 

이번 수정본은 그 흐름을 이렇게 바꿨다.

FocusCapability, FocusMode("auto" | "manual") 추가

set_focus_mode(), set_manual_focus_value(), configure_focus() 추가

카메라 open/reopen 시점에만 focus capability를 probe

선택된 focus mode를 open/reopen 시점과 명시적 설정 변경 시점에만 적용

set_auth_ready() / set_scanning_enabled()에서는 더 이상 autofocus를 재호출하지 않음

라이브 조절 시 cap.read()와 cap.set()/get()이 충돌하지 않게 _cap_io_lock 추가

덤으로 pyzbar.decode()는 QRCODE만 보도록 제한

OpenCV 문서에는 CAP_PROP_FOCUS, CAP_PROP_AUTOFOCUS, CAP_PROP_SETTINGS가 있고 CAP_PROP_SETTINGS는 DSHOW에서만 설정 창을 띄운다고 되어 있다. 반면 Windows의 카메라 제어 문서는 focus UI를 만들 때 Supported, Min, Max, Step을 보고 슬라이더 범위를 잡으라고 안내한다. 그래서 이번 패치의 capability probe는 “OpenCV만으로 가능한 범위의 추정형”이고, 정확한 슬라이더 범위까지 장치별로 잡으려면 나중에 Windows 네이티브 카메라 API로 내려가는 게 더 정확하다. 

또 한 가지 중요한 점은, fixed-focus 웹캠은 소프트웨어에서 초점 조절 자체가 안 된다. Logitech 공식 문서도 auto-focus 카메라는 auto-focus를 끄고 슬라이더로 조절할 수 있지만, fixed-focus 카메라는 조절 옵션이 없다고 구분한다. 그래서 이 패치는 “모든 기종에서 같은 코드베이스로 동작”하게 만드는 방향이지, “모든 기종에서 manual focus가 반드시 활성화”되게 만드는 건 아니다. 미지원 카메라에서는 set_focus_mode("manual")이 False를 돌려주게 했다. 

QR 쪽은 현재 repo가 decode(frame) 전체 심볼 검색을 쓰고 있는데, pyzbar는 OpenCV의 numpy.ndarray 입력을 받을 수 있고 symbols=[ZBarSymbol.QRCODE]로 QR만 찾도록 제한할 수 있다. 그래서 focus 패치에 같이 넣어도 기존 방식 안정성을 크게 건드리지 않으면서 약간의 스캔 낭비를 줄일 수 있다. 

호출은 이렇게 하면 된다.

scanner = ScannerView(
    camera_index=0,
    on_frame_ready=on_frame_ready,
    focus_mode="auto",          # 기본은 auto
    manual_focus_value=8.0,     # manual일 때 쓸 값
)

# 카메라 열고 나서 capability 확인
cap = scanner.get_focus_capability()
print(cap.autofocus_supported, cap.manual_focus_supported)

# Auto로 전환
scanner.set_focus_mode("auto")

# Manual로 전환
ok = scanner.set_focus_mode("manual")
if ok:
    scanner.set_manual_focus_value(8.0)

# 값만 바꿔서 라이브 반영
scanner.set_manual_focus_value(10.0)
