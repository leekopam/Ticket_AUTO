## 작업 이력, 피드백, QR 체크리스트, 자체 자동 테스트

## 작업 시도 이력 · 사용자 피드백 · QR 체크리스트 · 자동 검증 공통 규칙

이 섹션은 모든 프로젝트에서 기능 회귀, 지시 누락, 같은 실패 반복, 장기 작업의 문맥 손실을 줄이기 위한 공통 운영 규칙이다.

### 1. Attempt Ledger: 시도한 방법과 결과 기록

작업 중 의미 있는 시도, 실패, 성공, 보류, 되돌림이 발생하면 프로젝트에 다음 문서를 유지한다.

- `docs/ai-worklog/attempt-log.md`

각 항목은 아래 정보를 포함한다.

| 항목 | 설명 |
|---|---|
| 날짜/작업 ID | 작업을 구분할 수 있는 날짜 또는 짧은 ID |
| 목표 | 무엇을 해결하려 했는지 |
| 시도한 방법 | 실제 적용한 접근법 |
| 결과 | 성공 / 실패 / 부분 성공 / 보류 / 롤백 |
| 근거 | 테스트, 빌드, 스크린샷, 로그, 사용자 확인 등 |
| 실패 원인 | 실패 또는 부분 성공이면 원인 가설 |
| 다음 조치 | 반복하지 않기 위한 다음 액션 |
| 사용자 피드백 | 사용자가 준 평가, 수정 요구, 선호 |

중요: 같은 실패를 반복하지 않도록 새 작업 시작 전 관련 attempt-log를 먼저 확인한다.

### 2. User Feedback Ledger: 사용자 피드백 누적

사용자의 피드백, 선호, 금지 조건, 반복 지적은 다음 문서에 누적한다.

- `docs/ai-worklog/user-feedback.md`

사용자 피드백은 단순 대화 기록이 아니라 다음 작업에 영향을 주는 운영 지식으로 정리한다.

예:

```md
## 2026-04-20 / Godfield UI
- 피드백: 진행률과 남은 작업 브리핑을 매 턴 유지할 것.
- 적용 규칙: CONTINUOUS_DEV_LOOP 보고 형식에 전체 진행률/현재 진행률/남은 작업 포함.
- 상태: 적용 중
```

### 3. 중복 내용 병합 규칙

문서가 길어지거나 같은 내용이 반복되면 다음 원칙으로 병합한다.

1. 같은 금지 조건, 완료 조건, 테스트 명령은 하나의 정본 위치로 합친다.
2. 중복된 지시가 있으면 더 구체적이고 최신인 항목을 남긴다.
3. 오래된 시도 내역은 삭제하지 말고 `docs/ai-worklog/archive/` 또는 압축 요약으로 이동한다.
4. 규칙이 충돌하면 사용자 최신 지시 > 프로젝트 `AGENTS.md` > skill > 일반 관행 순으로 판단한다.
5. 병합 시 “무엇을 병합했고 무엇을 삭제/이동했는지”를 attempt-log에 남긴다.

### 4. 컨텍스트 압축 규칙

다음 중 하나에 해당하면 컨텍스트 압축을 수행한다.

- `attempt-log.md`가 너무 길어져 현재 작업 판단에 방해될 때
- 같은 내용이 3회 이상 반복될 때
- 장기 작업에서 진행상태가 흩어졌을 때
- 에이전트가 이미 완료한 항목을 다시 계획하거나 반복할 때

압축 산출물은 다음 파일이다.

- `docs/ai-worklog/context-summary.md`

압축 요약은 아래 구조를 따른다.

```md
# Context Summary

## 현재 목표

## 반드시 지켜야 할 금지 조건

## 완료된 항목

## 실패했던 접근과 반복 금지 이유

## 사용자 피드백 반영 사항

## 현재 열려 있는 리스크

## 다음 미완료 체크포인트
```

압축 후에는 새 작업 시작 시 전체 긴 로그보다 `context-summary.md`를 먼저 읽는다.

### 5. QR 체크리스트: Quality Review Checklist

여기서 QR은 Quality Review를 의미한다. 작업 완료 전 다음 문서를 사용한다.

- `docs/qa/QR_CHECKLIST.md`

최소 확인 항목:

- 요구사항을 빠뜨리지 않았는가?
- 수정 범위를 벗어나지 않았는가?
- 기존 정상 기능을 건드리지 않았는가?
- 금지 조건을 위반하지 않았는가?
- 테스트/빌드/린트/수동 QA를 실행했는가?
- 실행하지 못한 검증은 이유와 명령을 남겼는가?
- 사용자 피드백을 반영했는가?
- 같은 실패를 반복하지 않았는가?
- 필요한 경우 attempt-log, user-feedback, context-summary를 업데이트했는가?

### 6. 자체 자동 테스트 규칙

가능한 프로젝트에서는 다음 스크립트를 둔다.

- `scripts/harness/auto_self_test.ps1`

에이전트는 작업 완료 전 가능한 범위에서 이 스크립트를 실행한다. 실행하지 못하면 “미실행”이라고 밝히고, 이유와 수동 검증 절차를 남긴다.

자동 테스트는 최소한 다음을 확인한다.

1. 필수 문서 존재 여부
2. QR 체크리스트 존재 여부
3. attempt-log/user-feedback/context-summary 존재 여부
4. 프로젝트별 테스트 명령 실행 가능 여부
5. 금지 키워드 또는 금지 경로 침범 여부
6. 최근 작업 결과 파일 또는 검증 산출물 존재 여부

### 7. 보고 형식 추가

작업 종료 보고에는 기존 보고 형식에 아래 항목을 추가한다.

```md
### 시도/피드백 업데이트
- attempt-log 업데이트: 예/아니오, 이유
- user-feedback 업데이트: 예/아니오, 이유
- context-summary 업데이트: 예/아니오, 이유

### QR 체크리스트
- 통과:
- 실패/미확인:
- 자동 테스트 결과:
```
